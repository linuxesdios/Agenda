## ✨ Features

- 📅 Calendar and weekly appointment view
- ✅ Kanban task board, with criticality and reminders
- 📝 Quick notes ("brain dump")
- 🔖 Bookmarks / saved links
- 🔐 Encrypted password manager (`cryptography`)
- 🍅 Pomodoro timer
- 🧩 Templates and custom lists
- ☁️ Cross-device sync via private GitHub Gist
- 🔔 Scheduled local notifications
- 🖥️ Android home screen widget (with its own dark mode)
- 🌗 Dark mode, color palettes and language, all configurable
- 🌍 UI available in Spanish, English, Russian and Chinese

## 📂 Project structure

This is a single Flutter project: all application code lives in [lib/](lib/) and is compiled for each platform using the standard folders Flutter itself generates (`android/`, `ios/`, `linux/`, `macos/`, `web/`, `windows/`). These are not independent sub-projects — they share 100% of the logic and UI.

```
lib/
├── main.dart          # bootstrap, theme, window lifecycle
├── i18n/               # translation dictionary and language helpers
├── modelos/           # data entities (Cita, Tarea, Configuracion, ...)
├── estado/            # global app state (Provider/ChangeNotifier)
├── repositorios/      # persistence (SQLite and JSON) and its shared interface
├── servicios/         # notifications, encryption, Android widget, cloud sync
├── pantallas/         # main screens
└── widgets/           # reusable components and dialogs

android/ ios/ linux/ macos/ web/ windows/   # native shells generated by Flutter
installer/             # Inno Setup script for the Windows installer
```

## 🔨 Build from source

Common requirements: [Flutter SDK](https://docs.flutter.dev/get-started/install) ≥ 3.12 on your PATH, and `flutter pub get` run once at the repo root.

```bash
git clone https://github.com/linuxesdios/agenda.git
cd agenda
flutter pub get
```

### Windows

Requires Visual Studio 2022 with the **"Desktop development with C++"** workload.

```powershell
flutter build windows --release
```

Output: `build\windows\x64\runner\Release\agenda.exe` (+ required DLLs in the same folder).

To generate the `.exe` installer (requires [Inno Setup](https://jrsoftware.org/isinfo.php) 6 or newer):

```powershell
"C:\Program Files\Inno Setup 7\ISCC.exe" installer\agenda_setup.iss
```

Output: `installer\Output\AgendaSetup.exe`.

### Android

Requires the Android SDK (via Android Studio) with `flutter.sdk` / `sdk.dir` configured (Flutter generates `android/local.properties` automatically on the first build; that file is local to your machine and isn't version-controlled).

```bash
flutter build apk --release
```

Output: `build/app/outputs/flutter-apk/app-release.apk`.

### Linux

Requires the GTK 3 development dependencies (`libgtk-3-dev`, `cmake`, `ninja-build`, `clang`).

```bash
flutter build linux --release
```

Output: `build/linux/x64/release/bundle/` (full folder; `agenda` is the executable).

### macOS / iOS / Web

The `macos/`, `ios/` and `web/` folders are present (generated by Flutter) but aren't regularly built or tested in this project. They should work with the standard commands (`flutter build macos`, `flutter build ios`, `flutter build web`), but there's no guarantee — issues/PRs are welcome if you run into problems.

## ⬇️ Download a pre-built version

No need to build anything: every [Release](https://github.com/linuxesdios/agenda/releases) ships binaries already built by CI.

| Platform | File to download | What it is |
|---|---|---|
| 🪟 Windows | `AgendaSetup.exe` | Installer (recommended) — creates shortcuts and an uninstaller |
| 🪟 Windows | `agenda-windows-portable.zip` | Portable folder, no install needed — unzip and run `agenda.exe` |
| 🤖 Android | `app-release.apk` | Install after enabling "unknown sources" on your phone |
| 🐧 Linux | `agenda-linux-x64.tar.gz` | Portable bundle (best-effort, see note below) — unpack and run `agenda` |

### Cutting a new release

```bash
git tag v1.0.0
git push origin v1.0.0
```

This triggers `.github/workflows/release.yml`, which builds all 3 platforms and automatically publishes the Release with the binaries attached. It can also be run manually from the **Actions → Build & Release → Run workflow** tab (this doesn't publish a Release, it just leaves the build artifacts so you can verify the build works).

> **Note:** the Linux job runs on `ubuntu-latest` but was never tested locally (no Linux available on the development machine). It's marked `continue-on-error`, so if it fails it won't block the Windows/Android release — but it isn't guaranteed to work until the first real run.
